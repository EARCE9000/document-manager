ログインできるのは、台帳に登録したメールアドレスの利用者だけ(台帳に無い利用者は、IdP でログインできても入れない)。
  • 管理者: この管理の画面を使用可(利用者の追加・権限の変更・削除、切断、サーバーの設定)
  • 編集可: 文書の追加・アーカイブ・タグの編集など
  • 閲覧のみ: 文書の閲覧だけ
台帳から外すと、その人のログイン中のセッションと APIキーも止まる(台帳に入れ直しても、止めたキーは戻らない)。
不正なアクセスが疑われるときに、利用者をまとめて切断。切断で次の物が一式で止まり、認証からやり直し。
  • ログイン中のセッション(全部の端末・ブラウザ)
  • その利用者が発行した APIキー(元に戻せない。必要なら、本人が発行し直す)
  • 開いているモックアップの表示と、画面への知らせ(SSE)
切断だけでは防げないこと: ID とパスワードそのものが漏れているときは、切断してもまたログインされる(IdP の側でパスワードを変える)。 入れなくするには「利用者」のタブで台帳から外す。
全員ぶんの操作の記録(ログイン、文書とモックアップの書き込み、管理の操作、権限で断った呼び出し)。自分の分だけなら、文書一覧の右上の「操作履歴」でも確認可(全員が使用可)。 文書のダウンロードは、ここには残さない(サーバーの標準出力のログに残る)。
いま動いているサーバーの状態。ビルド日時はイメージを作った時刻、起動日時はこのコンテナが起動した時刻。 更新したはずなのにビルド日時が変わっていなければ、新しいイメージに入れ替わっていない。 部品の脆弱性が見つかったときは、「稼働中の部品の版」と「部品表」で、当てはまるかを確認(版は略さず表示)。 設定の変更は、すぐに反映し(複数台で動かしていれば、ほかの台にも 30 秒以内に効く)、監査ログに残る。
データベースが壊れていないかの確認と、データベースの記録と実際のファイルの照合。開いただけでは確認しない(前回の結果を出す)。
整合性の確認
破損は「書き込みは通るのに一部だけ読めない」形で進むことがあり、画面の上は正常に見える。 簡易は索引の整合の検査を省く。厳密は索引と表の整合まで検査するが、検査中はサーバーのほかの処理が止まる(データが多いほど長く掛かる)。
DB と実ファイルの照合
データベースの記録と、実際に保存されているファイルの食い違いを調べる(調べるだけで、何も変えない)。 アップロードが途中で失敗すると、ファイルだけが残ることがある。それらはアーカイブ済みとして登録し直せる。 逆にファイルが見つからない文書は、記録を消さない(置き場が一時的に見えていないだけのことがあり、消すとタグ・メモ・版のつなぎという戻せない情報まで失うため)。
文書を PDF にする 2 つの変換サービス(別々のコンテナ)の状態。動いていなくても、文書の登録・検索・概要のプレビューには響かない。
Office → PDF(体裁つき表示)再確認
Excel・Word・PowerPoint をレイアウトのついた PDF で表示するためのもの(LibreOffice の変換のため、細かい体裁は原本のダウンロードで確かめる前提)。
変換に失敗した文書
変換サービスが止まっていた間に登録された文書は、ここに残る。やり直すと、その場で変換し直す。
HTML・Markdown・MHTML・draw.io → PDF(PDF でダウンロード)
プレビューの見た目のまま 1 枚の長い PDF にして持ち出すためのもの。動いていなくても、プレビューの上の「PDF でダウンロード」が使えなくなるだけ。
Document Manager の資料を Miro のボードへ並べるための連携。ここで管理者が 1 回連携した Miro のアカウントで、選んだボードに資料を出し入れする(利用者ひとりずつの連携は要らない)。 Miro に出すのは資料の写しで、正本は Document Manager のまま。
