      Miro

      資料を Miro に書き出すのは、Claude Code などから頼んだときだけです(自動では書き出しません)。書き出すたびに、ボードの目印の向きに新しいフレームを作り、前に書き出したフレームには触りません(Miro に出すのは写しで、正本は Document Manager のままです)。ここでは、書き出す場所の目印を置き、ボードの目印と書き出しの履歴を見られます。
      ボードの目印
      書き出しの履歴
      目印を置く
      使い方
      1. 目印を置く: 上の欄で「ボードに置く」を押すと、ボードの空いている所に目印の付箋ができます。 左の一覧の名前の横のアイコンから Miro を開き、書き出したい場所までドラッグします。 Miro で付箋に直接「[DM]名前」「(右)」と書いても同じです。
      2. 書き出しを頼む: Claude Code(Document Manager の Skill)に、目印の名前を言って頼みます。
        「基本設計書と画面設計を、Miro の『設計書』の目印に書き出して」
        「定例の目印に、〇〇プロジェクトの議事録を十字で書き出して」(十字は、タグで資料を斜め 4 つに分けます)
      3. 手直しを頼む: 書き出したあとの並べ替えや、囲み・矢印の追加も頼めます(言わなければ、頼んだ人の最後の書き出しが対象)。

      ツール

      Document Manager を起点に作業するための支援ツールです。AIエージェント用の Skill は、ZIPを取ってエージェントに登録すると、話しかけるだけで各サービスを操作できるようになります。Skill の形式は共通なので、どのエージェントでも同じZIPを使えます(置き場所だけが違います)。「公式ツール」と付いたものは提供元が配っている道具で、入れ方を案内します。

                  切断の履歴

                  いま動いているサーバーの状態です。ビルド時刻はイメージが作られた時刻、起動時刻はこのコンテナが起動した時刻です。 更新したはずなのにビルド時刻が変わっていなければ、新しいイメージに入れ替わっていません。

                  機能のOn/Off

                  使う構成でだけ開ける機能です。切り替えはすぐ反映され、再起動は要りません(複数台で動かしている場合も全台に効きます)。

                  データベースのファイル

                  スキーマを更新すると新しいファイルを作り、古いファイルは消さずに残します(1つ前へ戻せるようにするため)。
                  データベースが壊れていないかを確認します。破損は「書き込みは通るのに一部だけ読めない」形で進むことがあり、画面上は正常に見えます。
                  簡易は索引の整合検査を省きます。厳密は索引と表の整合まで検査しますが、 検査中はサーバーの他の処理が止まります(データ量が多いほど長くかかります)。

                  DBと実ファイルの照合

                  データベースの記録と、実際に保存されているファイルの食い違いを調べます(調べるだけで、何も変更しません)。
                  アップロードが途中で失敗すると、ファイルだけが残ることがあります。それらはアーカイブ済みとして登録し直せます。
                  逆にファイルが見つからない文書は、記録を消しません。ストレージが一時的に見えていないだけの可能性があり、 消すとタグ・メモ・版の紐付けという二度と戻せない情報まで失うためです。
                  Excel / Word / PowerPoint をレイアウトのついたPDFで表示するための変換サービスの状態です(LibreOffice変換のため忠実な再現ではなく、細かい体裁は原本のダウンロードで確認する前提)。 動いていなくても文書の登録・検索・概要プレビューには影響しません(体裁つき表示だけが使えなくなります)。

                  変換に失敗した文書

                  変換サービスが停止していた間に登録された文書は、ここに残ります。再実行すると、その場で変換し直します。

                  PDFでダウンロード(HTML・Markdown・MHTML・draw.io)

                  HTML・Markdown・MHTML・draw.io の文書を、プレビューの見た目のまま1枚の長いPDFにして持ち出すための変換サービスの状態です(上のOffice用とは別のコンテナです)。 動いていなくても、プレビューの上の「PDFでダウンロード」が使えなくなるだけで、他には影響しません。
                  Document Manager の資料を Miro のボードへ並べるための連携です。ここで管理者が1回連携した Miro のアカウントで、選んだボードに資料を出し入れします(利用者ひとりずつの連携は要りません)。 Miro に出すのは資料の写しで、正本は Document Manager のままです。

                      使い方

                      資料を1か所に集めて、探して、そのままブラウザで読むためのものです。消す操作はありません(アーカイブは元に戻せます)。

                      資料を入れる

                      左の枠にドラッグ＆ドロップするか、枠を押してファイルを選びます。HTML / Markdown / PDF / 画像 / CSV・TSV / テキスト / draw.io / Excel・Word・PowerPoint が入ります。

                      Excel・Word・PowerPoint は内容の概要が表示されます(書式・図・グラフは再現しません)。原本はダウンロードしてください。

                      探す

                      検索欄はファイル名・タグ・メモ・本文が対象です。日本語も単語の区切りを気にせず探せます。

                      スペースで区切ると、すべてを含む資料だけに絞り込めます(全角スペースでも構いません)。請求書 2026年度 のように、ファイル名とタグにまたがる指定もできます。

                      「セマンティック検索」に印を付けると、言い換えや表記ゆれを含めて近いものを探します(この機能が有効な場合)。日付でも絞り込めます。

                      見る

                      一覧から選ぶと右に表示されます。ファイル名の右の外部リンクのアイコンで別ウィンドウに開けます。

                      Markdown の手順書にあるコマンドは、コードの枠にマウスを乗せると出る「コピー」で丸ごと取れます。draw.io と Mermaid はそのまま図として表示されます。

                      人にリンクを渡す

                      プレビュー上部にコピーのボタンが2つあります。

                      鎖のアイコン＝共有リンク。こちらを渡してください。資料を更新してもURLは変わらず、常に最新版が開きます。

                      栞のアイコン＝この版のリンク。更新しても、その時点の版を指したままです。「この版を見てほしい」と伝えたいとき(レビュー依頼・議事録への引用)に使います。

                      資料は更新のたびに別のものとして保存されます。版のリンクを渡すと、相手は更新に気づかないまま古い版を見続けます(リンク自体は開けるため)。迷ったら鎖のほうです。

                      共有リンクで開いている文書に新しい版が上がると、上に「新しい版があります」と出ます。押すまで表示は変わらないので、読んでいる途中で中身が入れ替わることはありません(テキスト・HTML・Markdown・図が対象。PDFと画像はそのまま開きます)。

                      開いたままログインの期限が切れた場合も、上に知らせが出ます。そのまま読み続けられますが、更新の確認はできなくなります。

                      プロジェクトごと渡すときは、プロジェクトの画面でプロジェクト名の右にある鎖のアイコンを押すと、そのプロジェクトを開くリンクをコピーできます。開いた人には、資料の一覧と説明書き(おしながき)が表示されます。

                      おしながきの「Markdownをコピー」で取れる一覧には、各資料を開くリンクが入ります。メールや議事録に貼れば、そこから資料を開けます。どのリンクも、開くにはログインが必要です。

                      メールなどで渡す — PDFでダウンロード

                      HTML・Markdown・draw.io の資料を、プレビュー上部の書類に下向き矢印のアイコンで PDF にして保存できます。HTML をそのままメールに添付すると、相手の環境では文字の羅列として出てしまうことがあるため、渡すときはこちらを使ってください。draw.io の図も、相手が draw.io を持っていなくても見られるようになります。

                      HTML・Markdown は画面で見たままの1枚の長いページになります(A4 には区切りません。区切ると表や図が途中で切れるためです)。横に長い表は、切れないようにページを右へ広げます。draw.io は図の1ページが PDF の1ページになり、紙の大きさは図の大きさに合わせます。

                      文字の形(フォント)は画面と少し違い、行の折り返し位置がずれることがあります。外部のサイトに置かれた画像は入りません(該当するときは保存時に知らせます)。渡す前に、PDF を開いて確かめてください。

                      整理する — タグとプロジェクト

                      タグは資料の性格を表す目印です。自由に付けられ、「タグ体系」の画面でよく使うものだけを並べて見られます。

                      プロジェクトは案件ごとの入れ物で、フォルダで階層を作れます。1つの資料を複数のプロジェクトに置けます。

                      プロジェクトの構成は既定では表示だけです。並べ替えや出し入れをするときは、見出しのトグルを押して編集モードにします。

                      おしながき

                      プロジェクト名を押すと、その案件にどんな資料が揃っていて、それぞれが何なのかを1枚にした一覧が出ます。引き継ぎやレビュー依頼でそのまま渡せます。

                      説明はその場で書けます(Ctrl+Enterで保存)。フォルダは章の見出しになります。「Markdownをコピー」でメールや議事録に貼れます。

                      版と関連文書

                      直した資料は「新しい版」として上げると、古い版は自動でアーカイブされ、タグとプロジェクトへの登録が引き継がれます。上部の「v1 › v2」から過去の版も開けます。

                      見積書と契約書のように、版ではないが関係のあるものは関連文書として結べます。

                      アーカイブ(消さない削除)

                      アーカイブは見えなくするだけで、ファイルは残ります。「アーカイブ」の画面からいつでも元に戻せます。

                      モックアップ

                      画面案のページ一式(ZIP)を登録すると、別ウィンドウで実際に動く状態で開けます。版を重ねると古いものは自動でアーカイブされます。

                      そのほか

                      他の人がアップロードやタグ付けをすると、右下に小さな通知が出ます(ベルのアイコンで止められます)。自分が行った操作は、時計のアイコンから30日分見られます。

                      権限は3種類です。閲覧のみの場合、アップロードやアーカイブの操作は表示されません。
