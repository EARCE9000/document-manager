# Miro の並べ方のモデル

Miro 連携([../miro.md](../miro.md))で、プロジェクトの枠の中に資料をどう並べるかの案を、draw.io の図にまとめたものです。
どれも案の段階で、いまの実装(フォルダの見出しごとに並べる)をこの形に変えたわけではありません。

図は [miro-layouts.drawio](miro-layouts.drawio) の 1 ファイルにまとめ、モデルごとにシート(ページ)を分けています。
各シートの右側に、そのモデルの決まりごと(振り分け・並び順・伸び方)を書いています。

| シート | 並べ方 | 向いているもの |
|---|---|---|
| 十字型(4区画) | 左上 要件定義〜設計、左下 テスト〜リリース(V 字で向かい合わせ)、右上 管理系、右下 ミーティング(週 × 曜日) | 工程のはっきりした開発プロジェクト |
| フォルダ列型 | 一番上のフォルダごとに 1 列、下の階層は ▼ の小見出し | フォルダ分けがそのまま工程や種類になっているもの |
| 時系列型 | 1 か月 = 1 行(上が古い)、月の中は日付順に左から右へ(7 枚で折り返す) | フォルダやタグが整っていないもの、経緯を追いたいとき |
| 左右分割・棚型 | 左半分 管理系、右半分 段階ごとの棚(準備 → 実施 → 実施後) | イベント・リリース作業・移行など、当日を中心に回る案件 |
| マトリクス型 | 行 = 機能、列 = 工程。資料の無いマスに「無し」を置く | 機能ごとに資料をそろえる開発。レビュー前の抜け漏れ点検 |
| 関係図・放射型 | 中心の資料から、関連文書の紐づけを 2 段目まで円に広げる | ある資料を直すときの影響の洗い出し |
| 版の流れ型 | 1 資料 = 1 行、版を登録日の位置に置いて矢印でつなぐ | 設計の経緯を追いたいとき |
| カンバン型 | 列 = 状態(作成中 → レビュー中 → 承認済み → 廃止) | レビュー待ちの溜まり具合を見たいとき |
| 読む順型 | 番号順の道(1 行 4 枚で蛇行)、枝番は寄り道、番号の無いものは参考 | 新しく入った人への引き継ぎ |
| 階層型 | 上から 方針 → 規約 → 手順 → 記録 のピラミッド | 標準・規約類、運用のプロジェクト |
| 地図型 | 構成図を中央に置き、各部品を説明する資料を周りに置いて点線でつなぐ | サーバやサービスが多い運用のプロジェクト |
| 鮮度表示 | 並べ方ではなく、最新版の更新からの日数でカードの色を変える(どのモデルにも重ねられる) | 長く続くプロジェクトの棚卸し |

振り分けや色分けの多くは、資料のタグ(`区分:` `工程:` `会議:` `段階:` `機能:` `状態:` `読む順:` `階層:` `部品:`)で決める前提です。タグがまだ無い資料でも並ぶように、各シートに「未分類」などの置き場を決めてあります。フォルダ列型・時系列型・版の流れ型・関係図・鮮度表示は、タグが無くても今ある情報だけで並びます。
