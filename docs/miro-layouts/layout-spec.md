# Miro の並べ方(レイアウト)の仕様

Miro 連携([../miro.md](../miro.md))で、プロジェクトの枠の中に資料を並べる型の仕様です。
図は [miro-layouts.drawio](miro-layouts.drawio) にあります(採用の型はシート名が「採用:」)。
**決まりごとは、図の右側の説明よりこの文書を正とします。**

- 実装済み(`app/lib/miro-layout.js`・`app/lib/miro-layout-plan.js`・`app/lib/miro-sync.js`)。実装で決めたことは 9 章の末尾。
- API 名・JSON の項目名は 9 章の末尾「実装で決めたこと」のとおり(8 章の表と例は案のときの名前。項目名は camelCase にした)。

## 1. 採用する型

| 型 | 並べ方 | タグ | 向いているもの |
|---|---|---|---|
| フォルダ列型(既定) | 一番上のフォルダごとに 1 列、下の階層は ▼ の小見出し | 見ない | フォルダ分けがそのまま工程や種類になっているもの |
| 時系列型 | 1 か月 = 1 行(上が古い)、月の中は日付順に左から右へ | 見ない(色分けだけ) | フォルダやタグが整っていないもの、経緯を追いたいとき |
| 左右分割・棚型 | 左半分 管理系、右半分 段階ごとの棚(準備 → 実施 → 実施後) | `区分:` `段階:` `会議:` | イベント・リリース作業・移行など、当日を中心に回る案件 |
| 十字型 | 左上 要件定義〜設計、左下 テスト〜リリース(V 字)、右上 管理系、右下 会議(週 × 曜日) | `区分:` `工程:` `会議:` | 工程のはっきりした開発プロジェクト |
| マトリクス型 | 行 = 機能、列 = 工程。資料の無いマスに「無し」を置く | `区分:` `機能:` `工程:` `会議:` `対象外:` | 機能ごとに資料をそろえる開発。抜け漏れの点検 |

- 型はプロジェクトごとに 1 つ選ぶ。最初はフォルダ列型。
- 1 枚のカード = 1 資料の最新版(題名・版・日付)。

## 2. 共通のタグ

1 つの言葉を全部の型で使う。値は下の表だけを正とし、型ごとに独自の値を作らない。

| タグ | 値(この順で並べる) | 使う型 |
|---|---|---|
| `区分:` | 管理 / 会議 | 棚・十字・マトリクス(どの型でも最優先) |
| `工程:` | 要件定義 / 基本設計 / 詳細設計 / 実装 / 単体テスト / 結合テスト / 受入テスト / リリース / 運用 | 十字・マトリクス |
| `段階:` | 準備 / 実施 / 実施後(回数があれば 実施 1 回目・実施 2 回目 …) | 棚 |
| `機能:` | プロジェクトごとに決める(並びはタグ体系 `/api/tag_order` に登録した順。未登録のものは、おしながき順で最初に出てきた順) | マトリクス |
| `会議:` | 定例 / 臨時(`区分:会議` だけで `会議:` が無ければ臨時) | 十字・棚・マトリクス |
| `対象外:` | 工程の値(例 `対象外:運用`) | マトリクス(その機能の行で、その工程のマスを灰色にする) |

- タグは今のタグと同じ文字列で持つ(例 `区分:管理`)。新しい仕組みは要らない。`:` より前を見出し、後ろを値として読む。
- 1 つの資料に、同じ見出しのタグは 1 つだけ(`機能:` も 1 つ)。2 つ以上あれば最初の 1 つを使い、報告(8 章)に出す。
  `対象外:` だけは複数可(その機能の行の資料のどれかに付いていれば、そのマスを対象外にする)。
- `区分:管理` か `区分:会議` が付いた資料は、工程や段階のタグがあっても成果物の区画には入れない。
- 表に無い値のタグは未分類として扱い、報告(8 章)に出す。
- 上の表の値(`機能:` 以外)はタグ体系(`/api/tag_order`)に登録し、画面のタグの並びもこの順にそろえる。
- フォルダ列型と時系列型は、置き場所を決めるのにタグを使わない。

## 3. タグが無いときの推定

フォルダ名・題名に含まれる言葉から推定する。

| 含まれる言葉 | 推定するタグ |
|---|---|
| 議事録・会議・打合せ・MTG・定例 | `区分:会議`(定例 を含めば `会議:定例`) |
| 計画・体制・WBS・スケジュール・課題・リスク・見積・予算 | `区分:管理` |
| 要件 | `工程:要件定義` |
| 基本設計・方式設計 | `工程:基本設計` |
| 詳細設計・API・DB 設計・画面設計 | `工程:詳細設計` |
| 単体テスト / 結合テスト / 受入テスト・UAT | `工程:単体テスト` / `工程:結合テスト` / `工程:受入テスト` |
| リリース・移行・切り替え | `工程:リリース` |
| 運用・保守・マニュアル | `工程:運用` |

- 付けたタグがあれば、推定より常にそちらが勝つ。
- 推定はタグとして保存しない。並べるときにだけ使い、報告(8 章)に「推定」として出す。確定は LLM 経由でタグを付けて行う。
- `段階:` と `機能:` は推定しない(未分類にする)。

## 4. 管理・会議・未分類の置き場

| 型 | 管理 | 会議 | 未分類 |
|---|---|---|---|
| フォルダ列 | フォルダの列のまま | フォルダの列のまま | フォルダに入っていない資料 → 右端の「その他」列 |
| 時系列 | 日付の位置に混ぜ、色で分ける | 日付の位置に混ぜ、色で分ける | 無し(日付は必ずある) |
| 棚 | 左半分 | `段階:` があればその棚、無ければ実施後の下の「会議」の棚(日付順) | 一番下の「未分類」の棚 |
| 十字 | 右上 | 右下(週 × 曜日) | 枠の下の「未分類」の段 |
| マトリクス | 表の下の「管理」の段 | その下の「会議」の段(日付順) | その下の「未分類」の段 |

専用の区画が無い型では、表や棚の下に 管理 → 会議 → 未分類 の順で段を置く。

「ほか n 件」にまとめた資料の実物(Miro のカード)は、未分類の段のさらに下の「ほか n 件の中身」の段に並べる
(上から 管理 → 会議 → 未分類 → ほか n 件の中身。管理・会議の段は、専用の区画がある型には無い)。
段の中は区画ごとに小見出し(例「右上: 管理系 のほか 3 件」)を付けてまとめ、どの「ほか n 件」の中身か分かるようにする。
人がこの段から区画へ動かしたカードは、5 章の「人が動かしたカードは動かさない」で扱う(特別な処理はしない)。
「ほか n 件」のカードは Document Manager のプロジェクトの画面へリンクする。

## 5. カードを動かしてよいとき

- Document Manager は、カードを置いた位置を覚えておく。
- 連動(自動)で動かしてよいのは、**覚えた位置のままのカードだけ**。人が Miro で動かしたカードは動かさない。
- 人が動かしたカードの資料に新しい版が上がっても、位置はそのままで中身だけ差し替える。
- 動かせないカードと重なりそうなときは、新しいカードを区画の空いている所へ置き、枠の上に「並べ直すと整います」の付箋を出す。
- 「並べ直し」(arrange)は全部を型どおりに置き直す(人が動かした配置も上書き)。実行前に、人が動かしたカードの枚数を返して確かめられるようにする。

押し下げを減らすため、型ごとに次のようにする。

| 型 | 決まり |
|---|---|
| フォルダ列 | 列の下へ足すだけなので押し下げは起きない |
| 時系列 | 折り返すのは最新の月だけ。過去の月に資料が足されたら、折り返さず右へ延ばす。並べ直しのときは全部の月を 7 枚で折り返す |
| 棚 | 棚の段が増えるときは下の棚を下げる(人が動かしたカードは残る) |
| 十字 | 上の 2 区画は大きさを固定し、入りきらない分は「ほか n 件」(中身は枠の下の「ほか n 件の中身」の段)。下の 2 区画だけ下へ伸ばし、十字の縦線を延ばす |
| マトリクス | 1 マス 2 枚まで。3 枚目からは「ほか n 件」にまとめ(中身は枠の下の「ほか n 件の中身」の段)、行の高さを変えない |

## 6. 型の選び方と切り替え

- 型はプロジェクトの Miro 連動の設定に持つ(項目名の案: `layout`。値は 8 章の API と同じ `folder-columns` など)。設定が無いプロジェクトはフォルダ列型。
- 連動を始めるときに型を選べるようにする(既定はフォルダ列型)。プロジェクトの画面と Skill の両方から変えられるようにする。
- 並べ直し(`POST .../miro/arrange`)に型を渡せるようにし、渡したときはその型に切り替えて並べ直す。
- 切り替えは「並べ直し」と同じ扱い。Document Manager が置いたカード・見出し・線を全部置き直す。
- 人が足した付箋や図形には触らない。
- 切り替える前に、切り替え先の型で報告(8 章)を出し、未分類の割合を見る。3 割を超えたら、先に LLM でタグを見直す。
- 直前の配置を 1 世代だけ覚えておき、「元の型に戻す」で戻せるようにする。

## 7. 型ごとの決まりごと

### 資料の日付の取り方(時系列型・十字型の右下・棚型と会議の段の並び)

1. 題名 → ファイル名の順に、次の書式の日付を探し、最初に見つかったものを使う。
   - `2026-10-17` `2026/10/17` `2026.10.17` `20261017` `2026年10月17日`
   - 年の無い `10/17` `10月17日` は、初版(最初の版)の登録日の年を補う(登録日より後の日付になるなら前の年)
2. 見つからなければ、初版の登録日を使い、報告(8 章)の `notes` に出す(`date_from_first_upload`)。版を上げても変わらず、何も覚えなくても報告と配置が一致する。
3. 版を重ねても日付は変えない(会議の日付などは資料ごとに決まっているため)。題名やファイル名が変わったときだけ取り直す。

### フォルダ列型

- 1 列 = 一番上の階層のフォルダ。列の順はおしながきのフォルダの順。列の幅はカード 2 枚分で固定。
- 列の中は、見出し「■ フォルダ名」の下におしながき順で 2 枚ずつ折り返す。下の階層のフォルダは「▼ フォルダ名」の小見出しを入れて続ける。
- 資料が増えたらその列の下へ足し、枠を下へ伸ばす(枠の上の端は動かさない)。フォルダが増えたら右に列を足す(「その他」列は常に右端)。

### 時系列型

- 1 行 = 1 か月。上が古く、下が新しい。資料の無い月も空の行として残す。
- 行の中は日付の早い順に左から右へ。日付は 題名・ファイル名の日付 → 無ければ初版の登録日。
- 1 行 7 枚まで。超えたら同じ月の中で次の段へ折り返す(最新の月だけ。5 章)。
- 色は区分・工程のタグで付ける(紫 要件定義〜実装・桃 単体テスト〜運用・灰 管理・緑 定例・橙 臨時。タグが無ければ灰)。
- 新しい月は下に行を足す。

### 左右分割・棚型

- 左半分は `区分:管理` の資料の格子(おしながき順)。
- 右半分は 1 棚 = 1 段階で、上から 準備 → 実施 → 実施後 → 会議 → 未分類。実施が何回もある案件は実施の棚を回ごとに分けてよい。
- 棚の中は日付の早い順に左から右へ(日付が無ければおしながき順)。1 段 4 枚まで、超えたら同じ棚の中で折り返す。
- 左と右は別々に下へ伸ばす。真ん中の線は長い方に合わせて引き直す。

### 十字型

- `区分:管理` → 右上、`区分:会議` → 右下。それ以外は `工程:` で決める(要件定義〜実装 → 左上、単体テスト〜運用 → 左下)。
- 左上は中心へ下りる階段(要件定義 → 基本設計 → 詳細設計)、左下は十字の横線で上下対称に中心から外へ戻る階段(単体テスト → 結合テスト → 受入テスト → リリース)。V 字で対になる工程を点線でつなぐ。`工程:実装` は詳細設計の段、`工程:運用` はリリースの下。
- 同じ工程に複数あれば段の中で横に並べる。
- 右上は格子(おしながき順)。
- 右下は 縦 = 週(古い週が上)、横 = 月〜金。日付は 題名・ファイル名の日付 → 無ければ初版の登録日。同じ日に複数あればマスの中で縦に重ね、行の高さはその週の最大に合わせる。会議の無い週も空の行として残す。土日に会議があったときだけ金曜の右に列を足す。`会議:定例` は緑、それ以外は臨時(橙)。
- 十字の中心に、プロジェクトの概要のカードを置く。資料ではなく Document Manager が作るカードで、プロジェクト名・説明・資料の件数・最終更新日を出し、Document Manager のプロジェクトの画面へリンクする。連動のたびに中身を更新する。

### マトリクス型

- 行 = 機能(`機能:`)、列 = 工程(`工程:`)。列は共通の工程の順で、資料が 1 件でもある工程だけ。
- 資料の無いマスは赤の点線「無し」を置く。`対象外:` で要らないと決めたマスは灰色の「対象外」。
- 機能か工程が決まらない資料は表の下の「未分類」の段へ。
- 機能が増えたら表の下に行、工程が増えたら右に列を足す。

## 8. LLM でタグを見直すための報告

タグ付けの見直しは、LLM(Claude の Document Manager Skill)から Document Manager に指示して行う。
そのため Document Manager は、指定した型で並べたらどうなるかと、直した方がよい点を JSON で返す。Miro には触らず、読むだけで出せるようにする。

API(案): `GET /api/projects/{id}/miro/layout-report?layout=folder-columns|timeline|split-shelves|quadrant-cross|matrix`
Skill(案): `miro-layout-report <プロジェクト> --layout <型>`

| 項目(案) | 中身 | 出す型 |
|---|---|---|
| `summary` | 区画ごとの件数、未分類の件数と割合 | 全部 |
| `placements` | 資料ごとに、置く区画と、その根拠(`tag` / `inferred` / `unclassified`)。推定なら推定したタグと使った言葉 | 全部 |
| `unclassified` | 未分類になる資料と理由(`no_phase_tag` `no_feature_tag` `no_process_tag` `unknown_value` など) | 棚・十字・マトリクス |
| `unknown_values` | 共通のタグの表に無い値と、近い値の候補 | 全部 |
| `overridden_tags` | 優先順位で使われなかったタグ(例 `区分:管理` があるので `工程:基本設計` を使わなかった) | 棚・十字・マトリクス |
| `gaps` | マトリクスの「無し」のマス(機能 × 工程) | マトリクス |
| `overflow` | 「ほか n 件」にまとめた区画と、その中の資料 | 十字・マトリクス |
| `notes` | フォルダ列: フォルダに入っていない資料 / 時系列: 題名から日付が取れず初版の登録日を使った資料 | フォルダ列・時系列 |

例(十字型):

```json
{
  "project": "Raspberry Pi",
  "layout": "quadrant-cross",
  "summary": {
    "total": 42,
    "unclassified": 6,
    "unclassified_ratio": 0.14,
    "areas": { "upper_left": 9, "lower_left": 7, "upper_right": 8, "lower_right": 12, "unclassified": 6 }
  },
  "placements": [
    { "document_id": "d-101", "title": "基本設計書", "area": "upper_left", "slot": "工程:基本設計", "basis": "tag" },
    { "document_id": "d-102", "title": "API 一覧", "area": "upper_left", "slot": "工程:詳細設計",
      "basis": "inferred", "inferred_tags": ["工程:詳細設計"], "matched_words": ["API"] }
  ],
  "unclassified": [
    { "document_id": "d-130", "title": "メモ", "reason": "no_process_tag" }
  ],
  "unknown_values": [
    { "document_id": "d-140", "tag": "工程:設計", "candidates": ["工程:基本設計", "工程:詳細設計"] }
  ],
  "overridden_tags": [
    { "document_id": "d-150", "used": "区分:管理", "ignored": ["工程:基本設計"] }
  ],
  "overflow": [
    { "area": "upper_right", "count": 3, "document_ids": ["d-160", "d-161", "d-162"] }
  ]
}
```

見直しの流れ:

1. LLM が型を指定して報告を取る。
2. 未分類・推定・表に無い値を、資料の題名や中身を読んでタグの案にする。
3. 人が案を確かめる。
4. LLM がタグを付け直す(既存のタグ付けの API・Skill を使う)。`PUT /api/documents/:id/tags` はタグ一式の置き換えなので、今のタグを読んでから、変える見出しのタグだけ差し替えて送る。
5. もう一度報告を取り、未分類が減ったのを確かめてから並べ直す。

## 9. 実装側で決めること

- API・Skill の名前と JSON の項目名(上は案)。
- カードを置いた位置の覚え方(Miro のアイテム ID ごとに、最後に置いた座標を持つ など)と、「人が動かした」とみなす差の大きさ。
- 「ほか n 件」のカードのリンク先(Document Manager のフォルダや一覧の画面 など)。
- 未分類の割合の目安(3 割)と、時系列型の 1 行の枚数(7 枚)・棚型の 1 段の枚数(4 枚)を設定で変えられるようにするか。

### 実装で決めたこと

実装は `app/lib/miro-layout.js`(振り分け)と `GET /api/projects/:id/miro/layout-report`(報告)。

- **名前**: API は上の案のまま(`layout-report`、型の ID も案のまま)。JSON の項目名は既存の API に合わせて camelCase にした
  (`documentId` `unclassifiedRatio` `inferredTags` `matchedWords` `unknownValues` `overriddenTags` `documentIds`)。
  区画の ID(`upper_left` など)と理由(`no_phase_tag` など)は値なので案のまま。
- **報告に足した項目**: `summary.slots`(区画 / 段ごとの件数)・`summary.inferred`(推定で決めた件数)・`summary.reviewRecommended`
  (タグを使う 3 つの型で未分類が目安を超えたら true)・`summary.excluded`(Miro に「出さない」にした資料。報告にも入れない)・
  `duplicateTags`(同じ見出しのタグが 2 つ以上)。型ごとに 棚 `shelves`、十字 `weeks`、マトリクス `features` `processes` `excludedCells`。
  `notes` の「初版の登録日を日付にした」(`date_from_first_upload`)は、日付を使う区画(棚・十字の右下・会議の段)でも出す。
- **根拠(`basis`)**: `tag` / `inferred` / `unclassified` に加えて、フォルダ列型は `folder`。
- **報告に入れる資料**: アーカイブ済みと、Miro に「出さない」にした資料は入れない(ボードに並ばないため)。連動していないプロジェクトでも出せる。
- **題名**: Document Manager の資料の題名はファイル名なので、推定と日付は「拡張子を除いたファイル名 → ファイル名」の順に見る。
  推定はそのあと、入っているフォルダ → その親 … の順。
- **推定の言葉**: 全角・半角、大文字・小文字、空白の有無は区別しない(`DB 設計` と `DB設計`、`mtg` と `MTG`)。言葉は 3 章の表のまま。
- **付けたタグと推定**: 見出しごとに、付けたタグがあればそれを使う。ほかに次の 3 つを決めた。
  - `工程:` か `段階:` のタグが付いていれば、`区分:` は推定しない(題名の「計画」などで成果物が管理に吸われないように)。
  - 表に無い値のタグしか無い見出しは推定せず、`unknown_value` で未分類にする(付けた人の意図を推定で上書きしない)。
  - `会議:` のタグだけが付いていれば `区分:会議` とみなす。`区分:会議` で `会議:` が無いときは、題名・フォルダ名に「定例」があれば 定例(推定)、無ければ臨時。
- **同じ見出しのタグが 2 つ以上**: 表の順で最初の値を使う(`機能:` は名前の順で最初)。`段階:実施 2 回目` などは `実施 2 回目` と書き方をそろえ、実施 と 実施後 のあいだに並べる。
- **日付**: 初版は版の鎖(前の版)を最初までさかのぼって決める。年の無い日付に補う年と登録日は、サーバーのタイムゾーンの日付で見る。週は月曜始まり。
- **「ほか n 件」**: 入る枚数を超えたら、入る枚数 − 1 枚を出し、残りを 1 枚にまとめる(図のマトリクスの「版管理の詳細 + ほか 2 件」と同じ)。
  十字型の右上は 9 枚(3 × 3)、左上は 1 段 4 枚、マトリクスは 1 マス 2 枚。
- **設定で変えられる数**: 未分類の目安(`MIRO_LAYOUT_REVIEW_RATIO`、既定 0.3)、時系列型の 1 行の枚数(`MIRO_LAYOUT_TIMELINE_PER_ROW`、既定 7)、
  棚型の 1 段の枚数(`MIRO_LAYOUT_SHELF_PER_ROW`、既定 4)。十字型・マトリクスの枚数は図の大きさに合わせた固定。
- **並べ方(3 段目)**: 位置の計算は `app/lib/miro-layout-plan.js`。カードの幅は 360、段の高さは A4 縦を基準にする。
  枚数で大きさを決める区画(十字型の上の 2 区画・マトリクスの行)も、縦長の資料(画像など)があるときだけ、その段を高くする(重ならないように)。
  棚型の左半分は 3 列、十字型の右上は 3 列。見出しの色は図の色(紫 `#eeedfe`・桃 `#fbeaf0`・灰 `#f1efe8`・緑 `#e1f5ee`・橙 `#faece7`・実施後 `#faeeda`)。
  十字型の V 字で対になる工程の点線は、まだ引いていない(Miro のコネクタが要るため。必要になったら足す)。
- **置いた位置の覚え方(4 段目)**: 資料ごとに、Document Manager が最後に置いた位置(`miro_items.placed_x` `placed_y`)と、Miro から読み直した今の位置を持つ。
  差が 2 より大きいか、枠の外へ出されていれば「人が動かした」とみなす。置いた位置を覚える前に置いた資料は、分からないので動かさない側に倒す。
  連動で資料を寄せるときは、動かす直前に Miro から今の位置を読み、前回の反映のあとで人が動かしていたら動かさない。
- **人や AI が場所を指示した資料**: 1 件ずつ動かす指示(`PATCH .../miro/items/:documentId`)とレイアウトを当てる指示(`POST .../miro/layout`)で置いた資料は、
  人が動かした資料と同じ扱いにする(連動では型どおりに寄せない。「並べ直す」を頼まれたときだけ置き直す)。「元の型に戻す」は、この区別も元に戻す。
- **連動で資料を足すとき**: 型どおりの配置を計算し直し、前に置いた資料は前の並び(上から・左から)のまま、新しい資料はその後ろに足す。
  フォルダ列型の列・マトリクスの行と列も前の並びのまま、新しいものを右・下に足す。区画の見出し・線は、前と同じものは残して変わったものだけ置き直す。
- **ぶつかるとき**: 型どおりの場所が人の動かした資料とぶつかる新しい資料は、枠の中のいちばん下の空いている所に置く。
  付箋「並べ直すと整います」は枠の上(枠の外、左上の角の上)に 1 枚だけ出し、要らなくなったら消す。並べ直すと片付ける。
- **並べ直す前の確かめ**: `GET /api/projects/:id/miro/arrange-check?layout=…` で、人が動かした資料の枚数(`humanMoved`)と一覧、
  切り替え先の型での未分類の割合を返す(Miro から今の位置を読むだけで、ボードは変えない)。
- **タグ体系への登録(6 段目)**: タグ体系は管理者が並べ替えるものなので、自動では書き換えない。タグ体系の管理画面の
  「**Miro の並べ方のタグをそろえる**」を押すと、2 章の表の値(`機能:` 以外)を表の順で下書きに入れる(すでにあるものは、
  最初に出てくる位置にまとめて表の順に並べ直す。ほかのタグの順は変えない)。「保存」を押すまでは反映しない。
  一覧は `GET /api/miro/layout-tags` で取れる。
