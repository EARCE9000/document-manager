# HTML → PDF 変換サービス (pdf-converter)

HTML・Markdown・MHTML の文書を、**プレビューで見たままの1枚の長いPDF**にするための、小さなHTTPサービスです。
draw.io の図(`.drawio`)も、**図の1ページを紙1枚**にしてPDFにします。
Chromium(ブラウザと同じ描画エンジン)をヘッドレスで動かします。

HTMLで作った資料をメールに添付すると、相手の環境ではテキストとして出てしまうことがあります。
人に渡すための形として、画面の「PDFでダウンロード」から使います。

アプリ本体([../app/](../app/))からは内部ネットワーク経由でのみ呼び出し、**外部には公開しません**。

## どういうPDFになるか

- **1枚の長いページ**にします。A4には区切りません(区切ると表や図がページの途中で切れ、右へはみ出した分が欠けるため)。
  画面で読んでもらう用途向けで、紙に刷る用途には向きません。
- **画面用の見た目**で描きます(印刷用のCSS `@media print` は使いません)。背景色も出ます。
- 幅は 1280px。**横に長い表・1行が長いコードがあれば、切れないようにページを右へ広げます**。
- 高さを区切ってスクロールさせている枠は、**開いて中身を全部出します**(PDFではスクロールできないため)。
- PDFの1ページは200インチ(19200px。A4でおよそ17枚分)までです。**それより長い文書は、同じ大きさの
  ページへ続きます**。文字の行は切れませんが、枠で囲んだ箱はページの境目で分かれます。
- 文字は文字として入ります(検索・コピーできます)。

### 画面と変わるところ

**フォントが違います。** 文書が指定するフォント(游ゴシック・メイリオ・ヒラギノ・Segoe UI など)は再配布
できないため、このコンテナにはありません。日本語は **BIZ UDPゴシック / BIZ UDP明朝**、コードは
Liberation Mono で描きます。字の形と幅が少し変わるので、**行の折り返し位置がブラウザのプレビューと
ずれることがあります**(実際の文書52件での高さの差は、HTMLで中央値 +1.2%・最大 +5%、Markdownで中央値 +0.5%)。
配置そのものは変わりません。フォントの選び方は [fonts.conf](fonts.conf) に書いてあります。

**外部に置かれた画像・フォント・CSSは入りません。** 変換時に外部へは接続しないためです(下の「隔離」)。
1つのファイルに全部埋め込まれている文書であれば影響ありません。読み込まなかった件数は応答ヘッダー
`X-Blocked-Requests` で返し、画面は保存時にその旨を知らせます。

**スクリプトは動きません。** アプリのプレビューがスクリプトを止めて見せているので、同じ条件で描きます。
スクリプトで描くグラフなどは、プレビューでもPDFでも出ません。「画面で見えているもの = PDFに写るもの」です。

**操作して開く部分**(折りたたみ・タブ)は、開いた時点の状態だけが写ります。

### draw.io の図

- **図の1ページが紙1枚**になり、紙の大きさは**ページごとに図の大きさ**に合わせます(余白は周りに12px)。
  画面より大きい図も縮めません。200インチ(19200px)を超える図だけ、縦横の比を保って収まるまで縮めます
- 描くのは、アプリが画面で使っている draw.io 公式のビューアと**同じ版**です(イメージに同梱。
  [../app/static/vendor/drawio/](../app/static/vendor/drawio/))。回路図の記号などの拡張図形も同梱から読みます
- 圧縮形式で保存された図(古い版や Web 版の draw.io が保存する形)も描けます
- 外部のサイトに置かれた画像は入りません(画面のプレビューでも出ません)。件数は `X-Blocked-Requests` で返します
- 数式(LaTeX)は、画面と同じく記号のまま出ます
- 実際の図22件(回路図・配線図・ピン配置図など。最大5ページ)で、ページ数・大きさ・記号・表・日本語が
  draw.io で見たとおりに出ることを確かめています

## なぜ別のイメージなのか

Office用の変換サービス([../converter/](../converter/))とも、アプリ本体とも分けています。

- 使う人だけが入れればよい(Chromium一式で、取得サイズが約410MBある)
- **ブラウザのエンジンで、他人が作ったHTMLを開く**。Officeの変換とは危険の種類が違うので、同じコンテナ・
  同じネットワークに同居させない(片方が破られても、もう片方へ届かせない)

動かさない構成では、画面に「PDFでダウンロード」が出ないだけで、他の機能には影響しません。

## 実測値 (amd64 / ローカル環境)

| 項目 | 実測 |
|---|---|
| イメージサイズ | 取得 約410MB / 展開後 約1.4GB(draw.io のビューア一式 約50MB を含む) |
| 待機時メモリ | 約16MB |
| ピークメモリ | **約170MB**(実際の文書52件を続けて変換したとき) |
| 変換時間 | **0.1〜0.4秒**(Chromiumの起動を含む。実際の文書52件で中央値 0.17秒・最大 0.38秒) |
| PDFの大きさ | 実際の文書で中央値 約300KB(最大 約770KB) |
| draw.io の変換時間 | **0.45〜2.0秒**(実際の図22件で中央値 0.57秒。5ページの図で2.0秒) |
| draw.io のPDFの大きさ | 実際の図で中央値 約150KB(最大 約1.1MB / 5ページ) |

Chromium は **155** (Debian 13 trixie の `chromium-headless-shell`。追加リポジトリ不要)。

## API

認証はありません(内部ネットワーク前提)。

### `GET /health`

```json
{"status":"ok","apiVersion":"1.1.0","chromium":"Chromium 155.0.8059.39","maxBytes":52428800,"timeoutSeconds":60,"viewportWidth":1280,"formats":["html","drawio"]}
```

`formats` は変換できる形式です(1.1.0 から)。`DRAWIO_DISABLED=1` のときは `["html"]` になります。

### `POST /convert`

本体にHTMLのバイト列(UTF-8)。`application/pdf` を返します。

| ヘッダー | 意味 |
|---|---|
| `X-Document-Id` | ログ用の文書ID(任意) |

**ファイル名は受け取りません。** ファイル名自体に患者名・施設名等が入り得るため、ログにも残しません。

| 応答 | 意味 |
|---|---|
| 200 | PDF。`X-Blocked-Requests` に、読み込まなかった外部の部品の数 |
| 400 | 本体が空 |
| 413 | 上限(`CONVERT_MAX_BYTES`)を超えた |
| 504 | 打ち切り時間(`CONVERT_TIMEOUT_SECONDS`)を超えた |
| 500 | 変換に失敗 |

### `POST /convert-drawio`

本体に `.drawio` のバイト列(XML)。`application/pdf` を返します(1.1.0 から)。ヘッダーと応答は
`/convert` と同じで、次が加わります。

| 応答 | 意味 |
|---|---|
| 404 | draw.io の変換を止めている(`DRAWIO_DISABLED=1`)。1.0.x のイメージにはこの受け口がない |
| 422 | draw.io の図として読めない(XMLが壊れている・ページが無い・別の形式) |

## 設定

| 環境変数 | 既定値 | 意味 |
|---|---|---|
| `LISTEN_PORT` | `3000` | 待ち受けるポート |
| `CONVERT_MAX_BYTES` | `52428800` (50MB) | 受け付けるHTMLの上限 |
| `CONVERT_TIMEOUT_SECONDS` | `60` | 1件あたりの打ち切り |
| `PDF_VIEWPORT_WIDTH` | `1280` | 画面として描く幅(px)。幅で並びを変える文書の出方が変わる |
| `WORK_DIR` | `/tmp/convert` | 作業場所(tmpfsを割り当てる) |
| `DRAWIO_DISABLED` | (未設定) | `1` で draw.io の変換を止める。「スクリプトは一切動かさない」構成にしたいとき(下の「弱くなっているところ」) |

## 隔離

他人が作ったHTMLを開くので、何重にも閉じてあります。

**サービスの中で**

1. **スクリプトを動かさない** — ブラウザの設定で止め、さらにアプリの配信と同じCSP(`script-src 'none'`)を付ける。
   **draw.io だけは例外**で、図を描くために同梱のビューアを動かす(下の「弱くなっているところ」)
2. **文書そのもの以外を読み込ませない** — 読み込みを全て受け止め、文書以外は断る(外部の画像・CSS、
   `file://`、内部の宛先)。文書が自分を別のページへ移そうとした場合(meta refresh)は、移動だけを取り消す
3. **通信先を存在しないプロキシへ向ける** — 2 をすり抜けても、IPアドレスを直接書かれても届かない
4. **名前解決を全て失敗させる**
5. **変換1件ごとにChromiumを起動して捨てる** — 前の文書の状態を次へ持ち越さない

**コンテナとして**([../deploy/compose.yml](../deploy/compose.yml))

- 専用の内部ネットワーク(`document_manager_pdf` / `internal: true`)にだけ参加する。インターネットにも、
  Weaviate にも、Office用の変換サービスにも届かない
- ファイルシステムは読み取り専用、作業場所は tmpfs、ボリュームなし、非root、`no-new-privileges`、メモリ上限あり

隔離が実際に効いているかは、次で確かめられます(podman-compose の版によっては `internal` が反映されないため)。

```sh
CONVERTER=document_manager_pdf_converter ./deploy/check-converter-isolation.sh
```

### 弱くなっているところ

**Chromium 自身のサンドボックスは切っています(`--no-sandbox`)。** 権限を絞ったコンテナ(非root・
`no-new-privileges`・既定の seccomp)の中では立ち上げられないためです。スクリプトを動かさず通信も断って
いるので攻撃の入口は狭いですが、**画像や文字の描画そのものに欠陥があった場合の守りは、コンテナの隔離だけ**
になります。そのため:

これは podman に限った話ではなく、Docker でも同じです(既定のままでは「No usable sandbox」で起動に
失敗し、OS機能の絞り込み(seccomp)を外すと立ち上がることを確認済み)。Chromium のサンドボックスは
ユーザー名前空間を使いますが、コンテナは既定でそれを禁じています。

**切らずに動かす方法もあります**(未実装・未検証)。ユーザー名前空間だけを許す専用の seccomp プロファイルを
コンテナに渡す方法です。採っていない理由は、**文書のスクリプトを止めている**ためです。Chromium が
乗っ取られる攻撃の大半はスクリプトを足がかりにするので、残る入口(画像・フォント・HTML/CSS/SVGの解釈)は
狭く、上積みが小さいわりに、配るファイルと運用サーバごとの動作確認が増えます。さらに堅くしたく
なったときの選択肢として残してあります。

**draw.io の図では、スクリプトを動かします。** 図はXMLで、描くには draw.io 公式のビューア(JavaScript)が
要るためです。上の「文書のスクリプトを止めているので入口は狭い」という前提は、draw.io には当てはまりません。
次のように絞っています。

- 動くのは**イメージに同梱したビューアと描画用のスクリプトだけ**。図はデータとして渡す
- ページ全体に、アプリの図のビューアと同じCSP(`script-src 'self'`)を付ける。図のラベルにはHTMLを書けるが、
  そこに仕込まれたスクリプトやイベントハンドラは動かない(テストで確かめている)
- 通信の遮断(2〜4)とコンテナの隔離は HTML と同じ。破られても、届く先も持ち出せるものもない

それでも Chromium の欠陥はスクリプトの処理まわりに多いので、守りは HTML より一段弱くなります。狙うには、
ログインできる利用者が欠陥を突く細工をした図をわざわざ登録する必要があります。**「スクリプトは一切動かさない」
構成にしたい場合は、`DRAWIO_DISABLED=1` で draw.io の変換だけを止められます**(HTML・Markdown・MHTML は
そのまま使えます。draw.io の文書で「PDFでダウンロード」を押すと、止めていることを伝えるエラーになります)。

- このコンテナには何も持たせない(ボリュームなし・秘密の情報なし・外へ出られない)
- **イメージを毎週作り直す**([../.github/workflows/pdf-converter-publish.yml](../.github/workflows/pdf-converter-publish.yml))。
  コードが変わらなくても、Chromium のセキュリティ修正を取り込みます。運用側も定期的に取得し直してください

## 設計上の要点

- **依存パッケージなし**(Node標準モジュールのみ)。Chromium とは `--remote-debugging-pipe`(NUL区切りのJSON)で
  話すので、待ち受けるポートも増えません
- **変換は直列**(同時実行1)。非力なサーバでも他の処理を圧迫しないことを優先しています
- **止めるときは子プロセスごと**。親だけ止めると描画用のプロセスが残り、5回の変換で約400MBを持ったままに
  なりました。プロセスグループごと止め、PID 1 には `tini` を置いて後始末をさせています
- **紙に出す前の下ごしらえ**([server.js](server.js) の `PREPARE`)。そのまま印刷すると崩れる3点を直します
  - 「画面いっぱい」の指定(`vh` など)を、画面で見たときの大きさに固定する(紙では「ページの高さの1%」になり、
    長い1枚のページでは際限なく膨らむ)
  - スクロールする枠を開く
  - 文書の幅を画面で見たときの幅に固定する(ページを右へ広げても、中央寄せの本文がずれていかないように)
- **ページの高さに2pxの遊び**を足しています。内容の高さぴったりにすると、端数の差で最後の1行だけが
  2ページ目へ回ることがありました

## テスト

```sh
# 運用と同じ絞り方で立てる(ここで動かないものは運用でも動かない)
docker build -f pdf-converter/Dockerfile -t dm-pdf-converter:local .
docker run -d --name dm-pdf-converter -p 127.0.0.1:3012:3000 --tmpfs /tmp:rw,size=512m \
  --read-only --security-opt no-new-privileges:true --cap-drop ALL dm-pdf-converter:local
docker run -d --name dm-pdf-converter-limits -p 127.0.0.1:3013:3000 --tmpfs /tmp:rw,size=512m \
  --read-only -e CONVERT_MAX_BYTES=1048576 -e CONVERT_TIMEOUT_SECONDS=1 dm-pdf-converter:local

# 変換サービス単体(できたPDFのページ数・大きさ・フォント・文字まで見る)
PDF_CONVERTER_LIMITS_URL=http://127.0.0.1:3013 PDF_CONVERTER_CONTAINER=dm-pdf-converter \
  node pdf-converter/test/smoke.js

# アプリ本体と繋いだ結合テスト(アップロード → PDFでダウンロード → PDFの中身)
npm run test:pdf
```

[test/smoke.js](test/smoke.js) は、1枚に収まること・日本語が文字として入ること・横に長い表が切れないこと・
`vh` で膨らまないこと・スクリプトが動かないこと・外部や内部へ読みに行かないこと・変換後にプロセスが
残らないこと・上限と打ち切りを確かめます。**サービスをわざと壊した版で、それぞれ失敗することも確認済み**です
(遊びなし・下ごしらえなし・スクリプトを止めない・移動を取り消さない・総称のフォントを決めない・
親だけ止める・印刷用の見た目)。
